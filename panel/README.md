# 管理パネル（panel/）

作者と、GitHub Actions の時間を貸し借りする人（ホスト: [docs/guide/host.md](../docs/guide/host.md)）のためのページです。
リポジトリだけで動きます: 1 枚の静的なページ（GitHub Pages）が、サインインした人として GitHub の API と話します。GitHub に
置けないのは、「GitHub でサインイン」を仕上げる小さなサインインのサービス（[auth/](../auth/README.md)）1 つだけです
（Cloudflare Workers か、自分のサーバーの Docker）。

## はじめに（ラボの管理者が 1 回だけ）

1. この枝を既定の枝にマージし、パネルを開きます（Pages がまだなら、`pages.yml` を一度手で走らせるか、2 のあとで）。
   最初の 1 回だけ、トークンで入ります（「トークンで入る」: 下の表の権限の Fine-grained トークン）。
2. 「準備」のタブの **⚡ 全自動で準備する** を押します（サインインのサービスも置くなら、その前に Cloudflare の API トークン
   「Edit Cloudflare Workers」とアカウント ID を入れる）。パネルが Pages を有効にし、GitHub の App を作る画面へ行きます。
   あなたが押すのは GitHub の 2 つだけ: **Create GitHub App** と、ラボを選んである **Install**。戻ってくるたびに続きを
   自動で（鍵を秘密に・App を入れる画面へ・サービスを Cloudflare に置いてページに渡す）。1 つずつやるなら、上から順に。
   ⚠️ の行のボタンで、パネルから直せます:
   - **GitHub Pages** を有効に（Source: GitHub Actions）
   - **サインインのサービス**を置く: Cloudflare の API トークン（「Edit Cloudflare Workers」）と Account ID を入れると、その場で封じて
     秘密に登録し、`auth-deploy.yml` を始め、そのアドレスを変数 `LAB_AUTH_URL` に入れ、`pages.yml` でページに渡します。
     自分のサーバーなら URL を入れるだけ（[auth/README.md](../auth/README.md)）
   - **GitHub App を作る**: 1 回のクリックで GitHub の作成画面へ（権限は App の manifest に書いてあり、選ぶ必要はありません）。
     戻ってくると、App の鍵（`APP_PRIVATE_KEY`）・client secret（`APP_CLIENT_SECRET`）・受け渡しの署名の鍵（`AUTH_STATE_SECRET`）が
     その場で封じてラボの秘密に、App の id・名前・client ID が変数に入ります（ブラウザには残りません）。もう一度サービスを置くと、
     サービスにも App が入ります
   - **App をラボに入れる**（install）。組織なら組織の管理者が
3. それからは、誰でも「**GitHub でサインイン**」だけで入れます。できることは、App が入っているリポジトリで GitHub がその人に許す
   ことだけです（許可は App の導入で自動に決まり、トークンを作る人はいません）。

貸し手は、ホストに同じ App を入れるだけです（「準備」のリンクを貸し手に。**Only select repositories** でホストだけを選ぶ）。
そのあとは、借り手の「実行」から貸し手の Actions で走らせるのに、誰の個人のトークンも要りません。

## 入る

- **GitHub でサインイン**（ふつう）: サインインのサービス経由で GitHub の画面へ → 戻るとサインイン済み。トークンは 8 時間で、
  切れる前にサービスの `/refresh` で自動で新しくなります（GitHub は使うたびに新しい refresh token を出すので、同じブラウザの
  タブは 1 つずつ更新します）。「出る」でトークンを GitHub で取り消します。
- **トークンで入る**（最初の準備・サービスが無いとき）: Settings → Developer settings → Personal access tokens →
  **Fine-grained tokens**（パネルの「トークンを作る」が入れ物を開きます）。Repository access: ラボと、貸し借りのホストだけ。

| 権限 | 使うところ |
|---|---|
| Actions: Read and write | 進み具合・実行・止める・やり直す・成果物 |
| Contents: Read and write | ワークフローの入力・ポリシー・ホストの `.lab-host.json`（貸し手が条件を変える） |
| Secrets: Read and write | 秘密の名前の一覧・登録・消す（値は GitHub も返しません） |
| Variables: Read and write | Discord の知らせ方・「準備」の変数 |
| Issues: Read and write | 端末（ライブの issue）・監査ログ |
| Pages: Read and write | 「準備」の Pages |
| Pull requests: Read | 概要の開いている PR |

Fine-grained トークンが選べるのは 1 つの持ち主（自分か、入っている組織）のリポジトリだけです。ほかの人の個人アカウントのホストは、
「GitHub でサインイン」（貸し手が App を入れていれば見えます）か Classic トークン（`repo`・`workflow`）で。

**入れる人**: ラボのリポジトリに書き込める人（Write / Maintain / Admin）か、ホストの持ち主（貸し手）か、ホストに書き込める人
（借り手）。貸し手の初めての訪問では、その人のリポジトリから `.lab-host.json` のあるものを先に探します。

**見るだけの人**: 非公開（internal も）のラボで GitHub の役割が Read の人と、公開のラボで「メンバー」の「見るだけで入れる人」に
名前のある人（`.github/bds-lab-panel.json` の `viewers`）は、ラボを **見るだけ** で入れます: 概要・進み具合・アドオン・配布・成果物・
予約・統計・貸し借り・設定。実行・止める・やり直す・秘密・メンバーなど、GitHub がその人に許さない操作のボタンは出しません（押せない
ボタンを並べない）。秘密と変数は名前も読みません（GitHub は書ける人にだけ見せます）。公開のリポジトリは GitHub では誰でも読めるので、
`viewers` が決めるのは「パネルに入れるか」だけです。右上のアカウントの「ここでできること」に、その人に許されていることが出ます。

**知らない人（招かれていない人）**: サインインはできますが、できるのは **時間を貸すことだけ** です（「時間を貸す」の画面:
`ui/lend.mjs`）。ラボを **フォーク**（public・ラボと同じ中身。public なので GitHub の標準のランナーの分は掛かりません）し、
ラボの App をそのフォークだけに入れて「フォークで貸す」: フォークをラボに合わせ（Sync fork: ラボは `host.yml` を持っているので、
フォークにもそのまま入っています）、選んだ条件の `.lab-host.json` を書き、**`host.yml` だけ**を動くようにします（ラボのほかの
ワークフロー・定期実行・自動操縦は、貸し手のところでは止めたまま）。ホストにできるのは **その人自身の、このラボのフォーク** だけ、
許す仕事は AI もアカウントも要らないものだけ。そのあとも見えるのは「概要・貸し借り・設定」だけで、ラボの実行・秘密・メンバーには
触れません。「フォークで貸す」は最後に、ラボの持ち主をそのフォークに招きます: **フォークの全権限を持ち主に預けます**
（招待と、全権限のラボの App。フォークはラボの写しで、貸し手のほかのリポジトリには触れません）。ラボの持ち主は招かれなくても
App でそのフォークに頼め、招待を受ければパネルから合わせる・いつも貸すにする・LAB_HOSTS に入れる・外すができます。
ラボが新しくなったら、貸し手の「🔄 ラボに合わせる」か、持ち主の「🔄 全部合わせる」。

**貸す人はずっと貸す**: 管理者でも知らない人でも、フォークで貸すと全部の仕事・一日中・期限なしで、パネルに止めるボタンはありません。
知らない人は「🙋 参加をお願いする」でラボに issue を出せ、持ち主は「メンバー」の「参加のお願い」から招くか閉じます。

**管理者はいつも貸す**（`.github/bds-lab-panel.json` の `"adminsLend": true`。このラボはオン）: 持ち主のほかの管理者は、自分の
ラボのフォークで **いつも**（全部の仕事・一日中・期限なし・1 か月 50000 分: public のフォークは標準のランナーの分が掛かりません）
時間を貸します。貸すまでは、パネルはその人に「まず時間を貸します」だけを出し、管理者の操作を止めます（GitHub の上の権限は
変えません）。貸すと、フォークは持ち主に預けられ（招待）、ラボの変数 `LAB_HOSTS` に入り、「実行」の「空いている貸し手で
（auto）」と hostrun の `host: auto` の候補になります（hostrun は LAB_HOSTS のホストごとに App のトークンを作ります）。
持ち主の「メンバー」には管理者ごとに「⏱ いつも貸している」か「⚠ まだ」、「貸し借り」の「フォークで貸している人」には
フォークごとの条件・LAB_HOSTS・招待の「受ける」が出ます。

## いくつものアカウント

右上のアカウント（アバター）を押すと「アカウント」が開きます: いまの人・役割・ここでできること、**アカウントを切り替える**、
**アカウントを加える**（作者・貸し手・借り手などを同じブラウザに。「GitHub でサインイン」なら GitHub のアカウントを選ぶ画面から）、
このアカウントの設定、出る。それぞれのトークンと設定（ラボのリポジトリ・ホストの一覧・読み直す間隔・APP_CACHE_KEY）は
別々です。「覚える」を外したアカウントは、そのタブを閉じると忘れます。Discord の知らせの「管理パネル」ボタンは、その実行のある
ラボのアカウントで、その実行を開きます（`#runs?repo=<owner/repo>&run=<番号>`）。

## メンバー（管理者を足す）

「メンバー」のタブ（ラボの管理者だけが変えられます）: GitHub のユーザー名で **管理者・保守・書き込み・整理・見るだけ** として招く
（管理者にするときは確かめます）、役割を変える、外す、招待を取り消す。相手が GitHub の通知かメールで招待を受けると、その役割で
入れます。持ち主と自分の役割はここでは変えません。下の「役割」は、GitHub の役割ごとにパネルで許す操作のチェックの表で、
保存すると `.github/bds-lab-panel.json` に書きます（管理者はいつも全部）。

**👀 見るだけで入れる人**（公開のラボ）: GitHub のユーザー名を加えると、その人は「GitHub でサインイン」で見るだけで入れます（上の
「見るだけの人」）。GitHub の招待は要りません。保存すると `.github/bds-lab-panel.json` の `viewers` に書きます（200 人まで、
大文字と小文字は区別しません）。非公開のラボでは、Read で招いた人がそのまま見るだけで入れます。

メンバーを変えるには、GitHub のリポジトリの管理の権限が要ります: トークンなら Administration: Read and write、「GitHub でサインイン」
ならラボの App の administration: write（これから作る App には入っています。前に作った App は「準備」の「App の権限」に出るリンクで
足し、入れている人が承認します）。足りないときは GitHub の「Collaborators」へのリンクが出ます。

## 見た目（Minecraft 統合版の OreUI のように）と言葉

Minecraft 統合版の新しい画面（OreUI: 設定やワールドの一覧の画面）の形で作っています。並べ方・色・押し心地をゲームの画面に合わせました:

- **上の明るい帯**: 左に ☰（すべての画面と、何をするところか）、まん中に開いている画面の名前、右に ⚠（このページで起きたこと）・
  🔎 やりたいこと・🔔 お知らせ・アカウント。
- **下のドック**（スマホ。広い画面では帯の下のタブの列）: 画面を 5 つの組に。**ホーム**（概要・進み具合・実行・端末）・**作る**
  （アドオン・配布・成果物・予約）・**つなぐ**（連携・秘密・Discord・準備）・**チーム**（メンバー・貸し借り・監査）・**設定**（統計・
  設定）。押した組の画面は、その下の段（OreUI のタブの帯）で選びます。組を押すと、その組で最後に見ていた画面へ。その人が開けない
  画面と組は出しません（貸し手なら「ホーム・チーム・設定」の 3 つ）。
- **ボタンはゲームのテクスチャのとおり**: ゲームの OreUI のボタンの絵（`pressable_*.png`）を 1 ドットずつ読み、同じ色・同じ縁取りで
  描きます — 黒い縁、上と左が明るく、右上と左下の角に 1 ドット明るい点、右と下は少しだけ明るく、下に 2 ドットの影。指を乗せると
  面が暗く縁が明るく、押すと影が消えて 2 ドット沈みます。明るいボタン・緑の「する」・赤の「止める・消す」・タブの暗いボタンのどれも、
  面の色に白を混ぜる割合がゲームと同じです（`lib/styles.mjs` の `BEVEL`。`tests/ore-offline.mjs` がゲームの色と 1 段以内か確かめます）。
  押せないボタンはゲームの灰色、選んでいるタブは沈んだ暗い面、フォーカスは縁の外の白い輪。
- **ほかの部品**: 角の四角い面、I/O の印のスイッチ、ひし形の選択、沈んだ入力の欄、見出しの帯のカード、下から出るシート。
- **一覧の行**: 「進み具合」の実行は、行を押すと詳しく開きます（端の印が向きを変える。GitHub へのリンクは開いた中）。「概要」の
  最近の実行は、押すとパネルの「進み具合」でその実行を開きます（GitHub へ出ません）。パネルの外へ出るリンクには小さな印。
  「…を読んでいます…」「読み込んでいます…」の間は、その前でドットが順に光ります。
- **字はマイクラの字だけ**: どの言語も、ゲームと同じドットの字です。英数字は [IdreesInc/Minecraft-Font](https://github.com/IdreesInc/Minecraft-Font)
  （ゲームの字をファンが作り直したもの、SIL OFL）、日本語・韓国語・中国語などほかの字は、マイクラ自身がその字を描くのに使っている
  [GNU Unifont](https://unifoundry.com/unifont/)（SIL OFL）。日本語は日本の字形（Unifont JP）、繁體中文は台湾の字形（Unifont T）で
  出ます。どれもパネルの中に置き、外から読みません（`fonts/`: 画面の字の分だけ小さなファイルで読み、言語ごとのよく使う字は 1 つに。
  `fonts/README.md`）。見出し・ラベルの日本語は文節で折り返します（ブラウザが対応していれば）。
- **自分のマイクラのフォント**: 統合版を持っていれば、「設定」の「マイクラのフォント」で、ゲームのフォルダ（`data/fonts`）の
  フォント（Minecraft-Seven・Minecraft-Ten・Mojangles など）を選ぶと、この端末ではその字で出ます（本文と見出し）。ファイルは
  このブラウザの中（IndexedDB）だけに置き、どこにも送りません。ゲームのフォントのファイルはパネルに入れていません。
- **アイコン**: 12×12 のドットで描いたもの（`lib/pixelicons.mjs` → `node lab.mjs panel icons` が `icons.css` を書きます）。パネルの
  文の絵文字（✅ ⚠️ ❌ 🔔 🔎 …）は、その上にアイコンを描きます（`ui/ore.mjs`）: 文字はそのままなので、写す・読み上げ・試験は今までどおり。
- **スタイル**（「設定」の「🎨 スタイル」、この端末だけ）: 統合版そのままの色のほか、**かわいい**（サクラ・ミツバチ・アレイ）・
  **かっこいい**（ネザライト・ディープダーク・レルムズ）・**マイクラの場所**（ネザー・ジ・エンド・海・雪原）。形・縁取り・ドットの字は
  どれも OreUI のままで、色と、ページの後ろの淡いドットの模様が変わります。押すとすぐその色に（読み直し不要）、次に開いたときも
  描く前から（`early.js`）。どのスタイルも、字と背景の組み合わせはすべて WCAG AA（本文は 7:1）以上です（`node lab.mjs panel styles`
  が確かめてから `styles.css` を書きます）。
- **言葉**: 日本語・English・한국어・简体中文・繁體中文。入口のページの下と「設定」の「表示」で選べ（このブラウザに残ります）、
  選んでいなければブラウザの言語で。パネルのすべての文言（約 2,900）に、それぞれの言語の訳があります（`i18n/<言語>.json`、
  `node lab.mjs panel i18n` が足りないものを出します）。報告書・週の知らせ・issue・招待の文など、パネルが作って写す・送る文も
  その言語で。読むのは選んだ言語の辞書だけで、オフラインでも開けるようにその 1 つだけを端末に持ちます。予約の「日本語で書く」
  欄だけは、書き方の例を日本語のまま見せます（予約の文は日本語で読むため）。
- Mojang のもの（ゲームのフォント・テクスチャ・アイコン・ロゴ）は使っていません。ゲームの画面の色は、ゲームのファイルを見て
  数字として合わせ、絵は自分で描いています。
- 「見やすさ」（大きな字・はっきりした色・動きを減らす・リンクに下線）はこの見た目の上で、どのスタイルの上でも効きます（`a11y.css`、
  はっきりした色は `styles.css` の最後）。

## はじめての人にもわかるように

- **🔎 やりたいこと**（右上の 🔎、Ctrl/⌘+K、?）: 「秘密を登録したい」「アドオンを作りたい」「ひみつ」「止めたい」のように自分の言葉で
  入れると、そのための場所へ。ひらがな・カタカナ・言い方の違いを気にしません。パネルのことばの意味もその場で出ます。
- **はじめてのガイド**: 「概要」の一番上に、役割ごとの手順（持ち主は 7 つ: Pages・App・サインイン・Discord・最初の実行・貸し手）と
  進み具合、次にすることのボタン。
- **かんたん表示（はじめはこれ）**: あまり使わない画面（成果物・統計・Discord・メンバー・監査）と、説明や分析のカード
  （各画面の「？」、概要の 🧭・🩺 健康度・報告書・あなたのカード、実行の「ワークフローを選んで」、アドオンの 🎮・📝、
  配布の下書きと比較、古い秘密のカード、空き時間の見込み、設定のトークンの説明・デバッグ・ことばの意味）を隠します。
  隠すだけで、消してはいません: ☰ のいちばん下の「隠している画面」と 🔎 からは開けます（🔎「デバッグ」「健康度」は
  そのカードも出します）。「設定」の「表示」→「すべての機能を出す（上級）」で全部出ます（このブラウザだけ。☰ から戻せます）。
- **このタブでできること**（すべての機能を出したとき）: どのタブも、初めて開いたときに何のタブかを言葉で（2 回目からはたたんで）。
- **☰（画面の一覧）**: 上の帯の左の ☰ で、すべての画面を「いつも見る・作る・配る・つなぐ・鍵・人と時間・見る・このブラウザ」の組に
  分けて、何をするところかの一言と一緒に（ドックの 5 つの組と同じ分け方）。
- **知らせ（ドックの上に出る小さな箱）**: 同じ文は重ねず、3 つまで。✕ ですぐ消せます（失敗の知らせは 9 秒、ほかは 4.5 秒で消えます）。
- **なぜ落ちたか**: 落ちた実行の「詳しく」に「🩺 考えられる原因と直し方」（足りない秘密・時間切れ・回数の上限・権限・ネットワーク・
  BDS の取得・試験）と、直す場所へのボタン（足りない秘密は名前を入れて「秘密」へ）。
- **💡 アイデアからアドオンを作る**: 「実行」で、作りたいものを日本語で書くと ai-make.yml が AI で作り、本物のサーバーとプレイヤーで
  確かめてから、.mcaddon をリリースと Discord に届けます（ANTHROPIC_API_KEY か OPENAI_API_KEY。API の料金を使うので先に確かめます）。
- **📖 ことばの意味**: 「設定」の一番下に、パネルのことばの一覧。

## 会社で使うときに

- **🔍 アクセスの棚卸し**（「メンバー」）: 誰がどの役割で入れるか・最後の実行・気をつけること（90 日動きなし・貸していない管理者・
  7 日以上受けられていない招待）を一覧にし、CSV に書き出し（定期の見直しにそのまま）。
- **ポリシーの変更の記録**: 「役割」の表に、`.github/bds-lab-panel.json` を誰がいつ変えたか（コミット）。
- 監査ログ（「監査」）・役割の表・確かめる操作・操作がないときのサインアウトは、下の「役割と監査」に。

## アドオンを GitHub だけで（git clone も PC も要りません）

- **アドオン**: ラボのユニット（`bds/addons/<名前>`、あれば `end/plugins`・`ll/mods` も）を GitHub から一覧します: 題（TASK.md の見出し）・
  説明と版（manifest）・試験の数（tests.txt の `##`）・最新の .mcaddon（リリースから）。ボタンで:
  - **🧪 試験** / **📦 仕上げる**: `unit.yml` がラボの Actions で `node lab.mjs test|go -a <名前>`（入力は `common/unitci.mjs` が
    パネルと同じ規則で検査してから、引数で渡します: シェルを通しません）。仕上げの .mcaddon は実行の成果物 `unit-<名前>` に。
  - **✏️ ファイルを直す**: src/main.ts・tests.txt・TASK.md・manifest などをその場で直し、読んだときの sha つきで既定の枝に commit
    （ほかの人の変更は上書きしません）。「保存して試験」も。
  - **💡 AI で変える**: 「実行」の「アイデアからアドオンを作る」にそのユニットを入れて開きます（ai-make.yml）。
  - **🆕 新しく作る**: 名前・題・何をするか → `unit.yml`（job new）がひな形を作って既定の枝に入れます。
  - **🔀 既定の枝が守られているとき**（PR が要る会社のラボ）: 新しく作る・取り込むでできたユニットは、`unit.yml` が別の枝
    `lab-unit/<名前>-<実行の番号>` に置き、実行の注釈とまとめに「PR を作る」のリンクを出します。「アドオン」にも「PR を待っている
    ユニット」として出るので、そこから PR を作って入れます。ファイルを直す・予約の保存が守られた枝で断られたときは、GitHub の文
    （「Changes must be made through a pull request」「Repository rule violations found」など）と一緒に、守られていることを言います。
  - **📥 取り込む**: 人の .mcaddon・.mcpack・.zip（50 MB まで）を、その場で base64 にして専用の枝 `lab-incoming/<名前>` に置き、
    `unit.yml`（job import）がそこから取ってユニットにし、枝を消します（既定の枝の履歴にパックを残しません）。パックの中の名前と UUID は
    そのまま。ユニットの名前の欄が空なら、ファイル名から作ります（英小文字・数字・_。同じ名前のユニットがあれば先に言います）。
    大きさは 50 MB まで（ラボの本物の試しでは 49 MB のパックが通りました）。25 MB を超えると選んだときに一言出し、GitHub が
    大きすぎると断ったとき（422「too large to be processed」）は、そう日本語で言います。枝を作るのを ruleset が止めているとき
    （422「Reference update failed」）も、何を許せばよいかを言います。
- **配布**: リリースを新しい順に、ファイルの大きさ・ダウンロードの数・合計。リンクを写す、Discord に知らせる（notify.yml）。
- **予約**: 決めた時刻にワークフローを自動で始めます。ワークフローを選ぶと、その入力（yml の workflow_dispatch）がそのまま欄に
  なります。何時間ごと・毎日・毎週、時刻はちょうど（03:00 など）、時間帯（Asia/Tokyo など）。予約は `.github/bds-lab-schedule.json`
  に入り（読んだときの sha つきで保存）、毎時 7 分ごろの `schedule.yml` が `node lab.mjs schedule ci` で、いまの時の予約を既定の枝で
  始めます（そのときだけの短いトークンで。手で schedule.yml を始めると、何が始まるかを見せるだけ）。AI を使うものは料金を確かめてから。
  動かす予約がない間は schedule.yml が自分を止め（非公開のラボでも毎時の Actions の時間を使いません）、「予約」で動かす予約を保存すると
  また動きます（パネルを通さずにファイルを直したときは、Actions で schedule.yml を有効に）。
- **統計**: 実行（最大 300 件）と貸し手の host.yml の実行を、7・30・90 日で: 日ごとの積み上げ棒・通った割合の線・ワークフローごとの表と
  小さな線・曜日×時間のヒートマップ・貸し手の分。どれも「📋 数字で見る」で表に（色だけに頼りません）。
- **健康度と報告書**: 「概要」に、ラボの健康度（準備・実行の成功・古い秘密・アクセス・ポリシー・貸し手・版の 8 項目で 0〜100 点、A〜E）と
  直すと点が上がる 3 つ（そのタブへのボタン）。「会社向けの報告書」で、点の内訳・アクセスの見直し・ポリシー・最近の失敗・貸し手の分を
  Markdown のファイルに（このブラウザの中で作り、どこにも送りません）。

## 役割と監査（会社で使う）

ラボの既定の枝の **`.github/bds-lab-panel.json`** が、パネルで誰が何をできるかを決めます（無ければ今までどおり）:

```json
{
  "roles": { "admin": ["*"], "write": ["dispatch", "run.cancel"], "auditor": ["audit.read"] },
  "teams": { "auditors": "auditor" },
  "confirm": ["dispatch", "secrets.delete"],
  "idleMinutes": 30,
  "audit": "issue"
}
```

- `roles`: GitHub の役割（admin / maintain / write / triage / read）か、`teams` で決めた名前ごとに、許す操作（`dispatch`・`hostrun`・
  `secrets.put`・`secrets.delete`・`variables`・`run.cancel`・`lend`・`audit.read`、`*` は全部）。書いていない役割は何もできません。
- `teams`: 組織のチームの slug → 役割（書いた順で、その人が入っている最初のもの）。チームを読めないときは、その人がなりうる役割の
  全部が許すことだけ。
- `confirm`: 先に「よろしいですか」を聞く操作。`idleMinutes`: 操作がなければサインアウトする分（0: しない）。
- `audit`: `issue` ならパネルでの操作をラボの issue（ラベル `bds-lab-audit`、作ったらロック、900 件ごとに次へ）にその人自身の
  コメントで残し、「監査」のタブで絞り込み・CSV に。`auto`（既定）は非公開・internal のリポジトリだけ残します。
- ポリシーは **狭めるだけ**: GitHub が許さないことはパネルも許しません（GitHub の API がまた断ります）。正しくないファイルは
  「何も許さない」になります。このファイルを書ける人は GitHub で同じことができるので、CODEOWNERS や枝の保護で守ってください。

## どこの Actions で走らせるか

「実行」の一番上で選びます: **このラボ**（ラボ自身の Actions）か、**貸し手のホスト**（その人の Actions の分で。貸す条件が許す仕事だけ、
時間帯・最後の日の中、今月の分が上限の 80% に届くまで: GitHub が数えたホストの実行で）。ホストなら、ラボの
`.github/workflows/hostrun.yml` が `node lab.mjs host ci` で、ラボを `host run` と同じ中身でホストに送り、host.yml を始めます。
「結果を待つ」なら、ホストの結果がその実行の結果・まとめ・注釈・成果物（go の .mcaddon も）になり、notify が Discord に知らせます。
ホストへは、貸し手が App を入れていれば App の 1 時間のトークン（`common/ghapp.mjs`）で、なければ秘密 `LAB_HOST_TOKEN` で。

## 成果物をパネルで見る（スマホでも、zip を取らずに）

「進み具合」の実行（「詳しく」）と「成果物」のタブで、成果物の名前を押すと、その中身がパネルの上に開きます（`ui/viewer.mjs`）:

- **画像は画像で**: いちばん上に画像と動画の一覧（見えたものから読みます）。押すと大きく、← → で前後の画像、小さなテクスチャは
  ドットのまま大きく。**動画はその場で再生**（mp4・webm・mov。端末の録画 `recordings/*.mp4` も）。音（ogg・mp3・wav）も。
- **すべてのファイル**: 名前・フォルダで探す、種類（画像・動画・文字・ほか）で絞る。ログ・JSON・.lang・.mcfunction などは文字で
  （JSON は整形、長いものは始めだけ出して「全部出す」、UTF-8 と Shift_JIS）、それ以外は始めの 4 KB を 16 進で。
- **中のアーカイブも**: .mcaddon・.mcpack・.mcworld・.zip・.tar・.tar.gz・.zst を押すと、その中へ（何段でも）。
- **保存・共有**: どのファイルも「保存」、スマホでは「共有」（.mcaddon を共有から Minecraft に渡すと、そのまま入ります）。
- **公開リポジトリの端末の結果**（`results.sealed`: スクショ・録画・ログを runner が AES-256-GCM で封じたもの）: Secrets の
  `APP_CACHE_KEY`（無ければ `GOOGLE_AAS_TOKEN`）と同じ値を入れると、このブラウザの中で開いて、ほかのファイルと並べます（鍵は
  「この端末に覚える」でこのアカウントの「設定」に。覚えた鍵があれば次からは開くだけ）。鍵は外に出しません。
- **戻る**: ←・Esc・ブラウザ（スマホ）の戻るで 1 段ずつ、✕ で閉じる。アドレス `#files?repo=<owner/name>&art=<成果物の番号>`
  で、その成果物を開いたパネルに（AI 用の API の `artifacts_list` が `view` として渡します）。

GitHub は成果物を「保管場所への一時的な転送」でしか渡さず、ページはその行き先を読めません（ブラウザが隠します）。そこで
サインインのサービス（`auth/`、`GET /artifact`）が、**その人のトークンで** GitHub に聞いて行き先を受け取り、中身をそのまま流します
（覚えない・記録しない。トークンは GitHub にだけ渡し、保管場所には渡しません）。小さい成果物（12 MB まで）は 1 回で全部、大きな zip は
目次と開いたファイルの分だけ（Range）を読みます。サインインのサービスが無いパネル（トークンだけで入る）は、名前と「GitHub で取る」
のまま。サービスが古いときは、そう言います（「準備」でサインインのサービスを置き直す: auth-deploy）。

## 速く開く（Pages には 1 本にまとめて）

`pages.yml` は panel/ をそのまま置かず、`common/panel-bundle.mjs`（esbuild）で **1 本のスクリプトと小さな分け前**（`chunks/`）に
まとめて縮めてから置きます。`panel/` はそのまま（試験・AI 用の API・Worker はこちらを読みます）で、変わるのは配るものだけです。

- 最初に読むのは `panel.js` と、それが使う分け前だけ（`index.html` の `modulepreload` で同時に頼みます）。あまり開かないタブ
  （連携・メンバー・統計・予約・アドオン・配布・監査）と成果物ビューアは、それぞれ開いたときに読み（`panel.js` の `later()`）、
  ラボを一度描いたあと、手が空いたときに裏で全部読んでおくので、選んだときにはすぐ出ます。読めなかったら、その場に理由と「もう一度」。
- 実測（本物の Pages の今までの形と、まとめた形。スマホの幅・最初のカードが出るまで）: 頼むファイル 96 → 15、速い回線 0.43 →
  0.23 秒、CPU が 4 分の 1 のスマホ 0.88 → 0.56 秒、4G 3.75 → 1.17 秒、遅い回線（3G 相当）6.75 → 2.34 秒。
- できることは同じ: CSP はそのまま（自分のスクリプトだけ・eval なし）、`sw.js` もそのまま（`panel.js` の `import()` を読んで
  分け前も版ごとにしまうので、ネットなしでも開けます）。ソースマップを横に置くので、ブラウザの開発ツールでは元のファイルの名前で見えます。
- esbuild が無いときは、今までどおりそのまま置きます（遅いだけで同じに動きます。Actions に警告）。手元では
  `node common/panel-config.mjs <出力先>`（`--no-bundle` でそのまま）。
- 試験: `tests/bundle-offline.mjs`（あとで読むタブ・分け前・modulepreload・CSP・eval なし・esbuild なし）、`tests/panel-browser.mjs`
  は「サインインのサービスつき」と「版つき」のパネルをまとめた形で開き、`PANEL_BROWSER_SERVE=bundle` で全部のタブもまとめた形で。

## 守っていること

[SECURITY.md](../SECURITY.md)「管理パネル」に。要点: トークンはそのブラウザの中だけ（「覚える」なら localStorage、外せばそのタブ
だけ）。ページの CSP で、通信は GitHub の API・自分の config・サインインのサービスだけ、フォームは github.com だけ、画像と動画は
自分のもの・GitHub のアバター・ページの中で作った blob:（成果物の中身）だけ。サインインの
受け渡しは URL の # だけで、受け取ったらすぐ消し、そのタブが始めたもの（nonce）だけを受け取ります。秘密の値は、その場で
リポジトリの公開鍵で封じてから送ります（`lib/seal.mjs` を libsodium の出力で試験）。ほかのページの枠の中では何もしません。
