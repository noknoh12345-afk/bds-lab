# 予測（commit a8f8591 の SPEC.md 17 章のまま）

### 12 本目の予測（回す前に書いた: A = `-a geoui_web` scenario `app-aspects.txt`、B = `-a geoui_web_ws`（app.txt）の 2 本を並べて）

直したこと（どの画面の形でもぴったり・WebSocket）:
- **ぴったり（並べ方 z）**: ページと道具の絵を JSON UI の % で画面いっぱいに（`layout.js` fillImages: 下 90 %・上 10 %、ずらしなし）、ポインタは画面の
  高さに合わせるレンダラーで、横は画面の形のプロパティ `gweb:asp`（形 x 1000）で置く。形は (1) 開いた時にゲームが測る（**アスペクト比のプローブ**:
  160 個の小さな URL の画像、k 番目は形 a_k の箱の右端 — 画面が a_k より横長の時だけ画面の中。どれを取りに来たかで形が分かる。切り抜くパネルの中
  の組 c と、切り抜かない組 u。よくある形が段の中にあればそれ）、(2) `/web:size <幅>x<高さ>`、(3) `/web:fit`（左右の端の印にポインタの先を合わせて
  クリック）。分からない間は 24 の箱（今まで通り）。`/web:size box <形>` で箱。
- **WebSocket 版 geoui_web_ws**: @minecraft/server-net なし。プレイヤーが `/connect <サービス>:8787` を打つと、ゲームがサービスに WebSocket で
  つながり（ゲームが求めれば暗号化: ECDH P-384・AES-256-CFB8）、サービスが `/web:pump` をそのプレイヤーとして打ち、出力でスクリプトの要求を
  受け取る（BDS の試験 8/8: 出力は `@A cmd: {"n":"A","o":[…]}` で戻る）。絵はゲームがつないだアドレスから。チャットの `!文字` はページに打つ。
