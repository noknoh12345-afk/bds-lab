# Spectral Player ライブ — 声をその場でゲームの音に（近接ボイスチャット・立体音響）

曲を前もって変換するのではなく、届いた音を 50 ms ずつその場で変換して鳴らす道です。Discord のボイスチャンネルの声を、
つないだ Minecraft のプレイヤーの位置から 3D で鳴らせます（近づくと大きく、向きで左右が変わる。音はその人に付いて動く）。

## しくみ

```
声（48 kHz）─ web/live.js LiveEncoder ─ 50 ms ごとのフレーム ─ scriptevent spectral:live {…} ─ アドオン（src/main.ts LiveStream / LivePlayer）
              （先を見ない分析: 直近 43 ms だけ）   （1 行 ~150 字、20 行/秒）                 （2 tick 後ろを鳴らす: ジッターバッファ 100 ms）
```

- **フレーム**: 声の数 N ビットのマスク（変わった声。1 秒に 1 回は全部）、その声ごとに音量の符号（bit 7 = 立ち上がり）と、
  鳴っていれば音程の符号（2 バイト、16 Hz から 0.2 セント刻み）、8 本のノイズ帯域の符号、そのフレームへのフェード（2 ビット:
  5 / 12 / 25 / 50 ms）を声と帯域の分。音量の刻みは曲の形式と同じ（0.75 dB / 0.5 dB）
- **メッセージ**: `{"id": ストリーム, "s": 最初のフレームの番号, "f": base64 のフレーム, "m": メタ（最初だけ）, "at": 場所}`、
  終わりは `{"id": …, "end": true}`。サーバーのコンソールからも（/scriptevent は 2048 字まで: 1 フレーム ~150 字）、
  ほかのパックの `system.sendScriptEvent` からも
- **場所**（`at`）: `phones:<名前>[,<名前>…]`（ヘッドホン）・`speaker:x,y,z[,ディメンション]`（その場の 3D スピーカー: 全員で 1 組の音）・
  `near:x,y,z[,ディメンション]`（その場に、48 ブロック以内の人それぞれが自分だけの 3D の音で聞く）・`follow:<名前>`（その人から 3D で: 48 ブロック以内のほかの人それぞれに、その人だけが聞く 3D の音を話す人の位置に置く。話す本人には
  聞こえない。1.5 ブロック動いたら 1 tick に 8 音ずつ新しい場所に作り、2 tick 後に古い音から 1 tick のクロスフェードで引き継ぐ。近づいた人には足し、離れた人からは外す。
  48 ブロックは 3D の音を作る音量 3 で届く距離（実機: 16 ブロック × 音量、距離が倍で 6 dB 下がる）。`/spectral:range <音量>` で変えると、音を作る
  相手もその距離の内に。3D の音は高さ P_MIN で作る（作った直後の 100–200 ms は作ったときの高さと音量で鳴るため: SPEC.md）
  話す人がワールドにいなければ（抜けた・まだ入っていない）誰にも聞こえず、戻れば 10 tick 以内にまた聞こえる）
- **遅れ**: 変換の窓 43 ms ＋ 1 フレーム 50 ms ＋ ジッターバッファ 100 ms ＋ 運ぶ時間（その場の合成による分析を使うと ＋100 ms）。
  8 tick より遅れたら先へ飛び（遅れがたまらない）、4 tick 何も来なければ黙る（話し終わり）
- **その場の合成による分析**（**既定**、`--refine 2`。`--refine 0` で切る: 遅れが 100 ms 短い。web/live.js LiveRefiner）: 前もって変換する変換器の合成による分析（tools/spectral.py refine_client:
  各 tick の音の大きさとフェードを、実機の鳴り方の模型を通した音が元の声に ViSQOL の 32 帯域で一番近くなるように選ぶ）を、前から 1 回だけ、
  2 フレーム先まで見て（+100 ms）その場で。web/core.js が要る（ブラウザでは先に読み込む、Node では同じフォルダ）。ふつうの PC で
  24 声の 1 人分が実時間の約 3 割の計算。文の切れ目（橋渡しの無音 2 フレームのあと）で残りを出し切る
- **文の切れ目**: Discord は黙っている人の音を送らない。橋渡しは 120 ms 声が来なければ無音を 2 フレーム送る（声はエンコーダーが
  選んだフェードで消え、次の文はきれいな窓から、立ち上がりの印つきで始まる）。アドオンは 4 tick 何も来なかったあとのフレームを
  ひと続きの始まりとして、その最初のフレームから鳴らす（前の文の最後をもう一度鳴らさない、出だしを落とさない）
- **始め直し**: 番号 0 のフレームにメタがついたメッセージは新しいストリーム（送り手が止まって同じ id で始め直しても、古い番号の
  後ろで待たない）。場所を書いていなければ前の場所のまま
- **音の数**: 電話は同時に 32 音（実測）。1 人 16 声＋ノイズ 8 = 24 音なので、2 人が同時に話すと足りない分は静かな音から
  ゲームが落とす（どちらの声も聞こえる）。1 人ずつなら 24 声にもできる（`--voices 24`）
- **サーバーの負荷**: 命令は聞く人ごとに送る（follow / near はその人だけの音）。ローカルの本物の BDS で 24 声の話し声を 2–3 人が聞いて
  平均 52 命令/tick（1 人あたり約 20–26、実測: tests.txt の follow の節の /spectral:live、付いていく置き直しを含む）。スクリプトの時間は
  `/spectral:live` の ms/tick（その流れの分だけ）: 3 人が聞いて 0.4–0.8 ms/tick（実測、ローカルの本物の BDS 1.26.61.1）。話す人 × 近くで聞く人の数に比例するので、人の多い
  サーバーでは `--voices 8`〜`12` に（命令は声の数にほぼ比例して減る）

## 使う

ゲームの中: `/spectral:live`（流れているストリームの一覧）・`/spectral:live <id> phones|speaker|near|follow|stop [誰]`・
`/spectral:live_demo <曲> [phones|speaker|near|follow] [誰] [声の数] [場所]`（曲をライブの道で 1 フレームずつ送る: 試し）。

ファイルを声の代わりに: `node tools/live/encoder.mjs <音声> --live <id> --at follow:<名前> --realtime`（コンソールの行を
その速さで出す）・`--song <out.song.json>`（ライブのフレームを曲にして /spectral:play・エミュレーター・実機のリグで）・`--refine 2`
（その場の合成による分析）。

## Discord の橋渡し（tools/live/bridge.mjs）

1. Discord の開発者ページでボットを作り、トークンを `DISCORD_BOT_TOKEN` に。サーバーに招待（権限: 接続・アプリコマンド）。
   特別な intent（MESSAGE_CONTENT など）は要りません
2. `cd tools/live && npm install`（discord.js・@discordjs/voice（Discord の音声の暗号化と DAVE つき）・prism-media・opusscript）
3. サーバーをこの橋渡しから起動する: `DISCORD_BOT_TOKEN=… node tools/live/bridge.mjs --guild <サーバー ID> --channel <ボイスチャンネル ID> --bds <bedrock_server のフォルダ>`
   （自分で打つコンソールのコマンドもそのままサーバーへ）。ほかに `--stdout`（行を出すだけ）・`--lab`（bds-lab の `node lab.mjs up`）
4. Discord で各自 `/mc <ゲーマータグ>`（ボットのコマンド）: つないだ人だけがゲームで、その人の位置から聞こえる
5. 試し（Discord なし）: `node tools/live/bridge.mjs --fake <音声> --as <ゲーマータグ> --lab`

`node tools/live/test_bridge.mjs`: Discord なしで、ボイスチャンネルと同じ Opus（48 kHz ステレオ・20 ms）を同じ復号器で
ほどいて、コンソールの行（番号・メタ・場所・終わり・2048 字以内）、文の切れ目（無音 2 フレームで消えて、次の文は立ち上がりから:
フレームをアドオンと同じ読み方で読み戻す）と /mc のつなぎを確かめます。

ボイスチャンネルから外れた人のストリームは終わり、同じ人の次の文は同じストリームの続き（文ごとにゲームの音を作り直さない）。
声の接続が切れたら数秒は Discord のつなぎ直しを待ち、戻らなければ橋渡しはエラーで終わる（systemd や pm2 で起こし直す）。

## 質

**実機**（9 回目 run 41187515049: redroid の Android 14 に Play が入れた Minecraft 1.26.60.4、改造なし。録音の ViSQOL v3、実測）:
- ライブの道（1 フレームずつ script event、ジッターバッファ 2 tick、ヘッドホン）: 夏目漱石 **2.90**。同じデータを曲として鳴らすと 2.91:
  **送り方では落ちない**
- 3D: 聞く人の左 6 ブロックに置くと左が **+37.3 dB**、右に置くと **−46.1 dB**（lr_db）: 左右がはっきり分かれる。近くより約 11 dB 小さい
- ライブの変換（先を見ない、24 声）を曲として: 夏目漱石 2.73・ワーズワース 2.65・Name of Love 3.49。前もって変換したもの
  （2.91・2.73・3.59）より 0.09–0.18 低い
- 10 回目（run 41197478510）で、聞く人それぞれの 3D の音（near: follow と同じ鳴らし方）の左右を測る

**エミュレーター**（実機の模型、推測）: ライブの変換（24 声）は夏目漱石 2.92・ワーズワース 2.86、16 声で 2.89・2.85。前もって変換する
