# Spectral Player の測定リグ（本物のクライアントが鳴らした音を録る）: node lab.mjs app run -a spectral --device redroid
#   GitHub では Actions → redroid → Run workflow（addon: spectral, mode: run）。録音は app/runs/<実行>/audio/*.wav（成果物には入らない）。
#   数はジョブのログの `[spectral rig] <録音> <何>: {...}` の行（audio analyze）。録音そのものは `audio export` が Opus にして
#   tools/rig/rec_public.pem で暗号化し `[spectral rec]` の行でログへ（開けるのはその秘密鍵の持ち主だけ: tools/rig/rec_decode.mjs）。
# 音量: audio volume がメディアの音量を最大・ゲームの audio_ を 1（BGM 0）に（既定のままでは録音が元より約 39 dB 小さかった）。
# 試験曲: audio song がここで変換してコンソールから spectral:song で送り、execute as で /spectral:play（g_ = quality、l_ = light）。
# 天井: audio ceiling が元の抜粋を OGG のまま鳴らすだけのアドオン（bds/addons/spectral_ceil、実行の場で作る・コミットしない）を
#   作り、addon で BDS をそれで起動し直して入り直し、同じクライアント・同じ録音で鳴らす（c_<曲>）。天井との差 = 両方の ViSQOL の差。
# emu:<曲> = 同じ曲を tools/emu（spec.json = 実測で較正したクライアント）で鳴らしたものと録音の ViSQOL（依頼の較正の基準: 4.5 以上）。
# 一度で 40 分に収まるよう曲は 2 組（SONGS_A: ここ。もう一方は下の注釈）。重い変換は join の前、解析は録音の後ごと。

stop

launch

section join
join
until joined 300000
wait 5000
do time set noon
do gamerule dodaylightcycle false
do weather clear

section calib
audio start calib
do spectral:calib all
until server spectral calib\] end throughput 300000
wait 2000
audio stop
audio analyze calib all
audio export calib 96
