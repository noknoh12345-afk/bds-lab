# Spectral Player の測定リグ（本物のクライアントが鳴らした音を録る）: node lab.mjs app run -a spectral --device redroid
#   GitHub では Actions → redroid → Run workflow（addon: spectral, mode: run）。数はジョブのログの `[spectral rig]` の行、録音そのものは
#   `audio export` が Opus にして実行の成果物の public/spectral/rec/ に公開する（鍵なし: 管理パネルでサインインして聞ける・
#   notify.yml が Discord に送る・tools/rig/fetch_rec.py <run> で取る）。
# 13 回目（tools/exp/make_app.py tools/exp/app13.json）: 本体 1.2.0（電話の既定 +10 dB、3D の音は高さ P_MIN で作る、届く距離 48 ブロック）。
#   先に 3D（40 分で切れても残るように）: 夏目漱石をライブの道で、
#   na_ / nb_ / nc_ = 聞く人ごとの 3D（near）で左 3 / 24 / 46 ブロック、作る音量 3（既定）: 作った直後の「ピッ」が消えたか（11 回目の ka_ と比べる）・48 ブロックまで届くか
#   nf_ = 同じく左 3 ブロック、作る音量 1: 音量 3 と同じ大きさか（音量は届く距離だけ）
#   nd_ = 全員で 1 組のスピーカーで左 6 ブロック（9 回目の jl_ と同じ置き方、dimension.playSound の道）
#   ne_ = スピーカーで左 52 ブロック、作る音量 4（16 × 4 = 64 ブロック）: 音の定義の max_distance 48 で切れるか
#   それから曲ごとに交互に（まとめ録り batch 13、前もって変換した曲 tools/exp/packs/run9・run10）:
#   d_ = 1.1.0 までの既定（+6 dB 向けの曲を +6 dB で）・o_ = 同じ曲を +10 dB で（前に変換した曲が 1.2.0 でどうなるか）・
#   e_ = +10 dB 向けの曲を +10 dB で（1.2.0 で変換した曲）。d_ と e_ は 11・12 回目と同じデータ（3 回目の同じ run の比べ）
