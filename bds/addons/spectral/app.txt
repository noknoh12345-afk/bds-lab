# Spectral Player の測定リグ（本物のクライアントが鳴らした音を録る）: node lab.mjs app run -a spectral --device redroid
#   GitHub では Actions → redroid → Run workflow（addon: spectral, mode: run）。数はジョブのログの `[spectral rig]` の行、録音そのものは
#   `audio export` が Opus にして実行の成果物の public/spectral/rec/ に公開する（鍵なし: 管理パネルでサインインして聞ける・
#   notify.yml が Discord に送る・tools/rig/fetch_rec.py <run> で取る）。
# 30 回目（tools/exp/make_app.py tools/exp/app30.json）: 貼り付けの 3 回目。29 回目（run 41362999116）で分かったこと（平文の ck_ の録音から）: フォームは開く、
#   OCR は Submit と灰色の例文（here / Paste the song）と見出し Song text を読める（題は読めない）、例文を押しても見出しの下を押しても入力欄に入り、
#   400 文字を 1 秒ほどで打てる。止まったのは打った後の Submit を押すところ（ENTER の後、^submit$）。その後の区切りは入力欄も押せなかった。
#   → フォームは Submit が読めるまで待つ（until text）、どの区切りも ck_<名前>_open から。打った後に入力欄を離れる 4 通り（ENTER・見出しを押す・
#   そのまま・戻る）を試して、それぞれ Submit が見えるか（ck_*_submit_seen）・押せたか・サーバーが答えたか。look は打った後に例文が消えたか（文字が入った）。
#   わざと失敗する手順（zz-never-on-screen-zz）は、リグに開いている画面を閉じさせるため（区切りの終わりに戻るで `shot world` まで）。最後に貼れた曲を鳴らして録る
