**3** が作る順番。事実は SPEC.md の実測（redroid の Android 14・Minecraft 1.26.60.4）と、Script API の定義（`node lab.mjs api`）から。

## 1. プロンプト（このまま渡せる）

```text
あなたは Minecraft 統合版（Bedrock）で「音」の可能性を広げる研究者兼音響エンジニアです。まだ何も作らず、
まず可能性の幅を最大まで広げ、そのあとで事実に照らして絞ってください。

# 目的（依頼者の言葉）
- MIDI などを正弦波から作らずに、1 tick（50 ms）の壁を超えて鳴らす。1 ms の差まで、元とほぼ同じに。ピアノなどの
  楽器の演奏を本物のマイクラの中で使う
- ゆっくり音声のような声を、MIDI と同じ原理（音素＝音符）で、人が楽に聞き取れる最高の質に（目標は Synthesizer V）。
  近接ボイスチャットの限界をそこまで上げる
- mp3 に近い音に: 高音がとても弱い・音割れ・ノイズキャンセリングのような消え方（とサー音）をなくす
- ゲームの中の web（OreUI のような画面を、bds-lab の GeoUI で）から、YouTube の URL → 取り込み → 変換 → 再生まで。
  マイクラそのままで、WebSocket（/connect）だけでも
- HTML の変換器（HTML → GeoUI）を使うたびによくして育てる

# 分かっている事実（実測は redroid の Android 14・Minecraft 1.26.60.4。ほかの端末は推測）
- スクリプトの命令は tick（50 ms）ごと。同じ tick の命令は 1.4 ms 以内に一緒に効く。tick ごとのばらつき σ 7.3 ms
- playSound はその場で SoundInstance を返す: fade(秒, 音量)（振幅で直線・最短 0.8 ms）・setVolume（2 倍まで正確）・
  setPitch（0.01–10 倍、0.12 セント以内）・seekTo(秒)（始めと同じ tick なら、その位置から鳴り始める）・pause・resume・
  stop・durationInfo.getPlaybackPosition()。world.afterEvents.soundCompleted、world.soundDefinitionRegistry.getDefinitions()
  （長さ・曲の情報 title/artist/genres/moods・タグで探せる）
- 同時に鳴るのは 32 音。超えると静かなもの・古いものから消える
- ゲームは 24 kHz で混ぜる（直線補間、12 kHz より上は 24 kHz − f に折り返す）。出力はファイルより −32.5 dB の 16 bit。
  混ぜた音はファイルの単位で約 2.0 で硬くクリップ
- is3D false の音はステレオのまま（左右の分離 67 dB）。3D の音は作ったときの音量で届く距離が決まり、作った直後の
  100–200 ms は作ったときの音量・高さで鳴る
- リソースパックの音は .ogg / .wav / .fsb（mp3 は確かめられていない）。サーバーのパックは参加するときに配られる
- フォームの入力欄は電話で 5000 文字まで。1 命令 約 12 バイト、24 声で 1 tick 平均 28 命令
- /wsserver（/connect）: チートが on の管理者がクライアントを外の WebSocket サーバーにつなぐ。サーバーはコマンドを送れて、
  イベント（チャット・動き・アイテムを使ったなど）を受け取れる。BDS ではアドオンのスクリプト・script event・プラグイン（Endstone /
  LeviLamina）も使える
- bds-lab の GeoUI: HUD の JSON UI に足した live_player_renderer がプレイヤーに付けた板を描いて作る 2D の画面。GeoUI Web は本物の
  Chromium が開いたページ（YouTube も）を URL の画像（profile_image_renderer）で F1 の全画面に出し、視点・攻撃・ジャンプで操作する
  （操作は @minecraft/server-net でサービスへ: BDS のみ。Android は LAN の http の絵を取りに行く）。HTML → GeoUI の変換器
  （bds/geoui/html/convert.mjs）はページを状態ごとに撮ってアトラスとボーンにし、フォームなしで動かす
- いまあるもの: 曲＝正弦波 24–48 声＋帯域ノイズ 8（tick ごとに setPitch・fade）、ライブ（1 フレームずつ script event）、3D、
  曲パック（BP）、貼り付け（SPZ2/SPA2）、Discord の橋渡し、変換ページ

# 進め方
1. 発散: 6 つの軸それぞれで、ふつうの案と突飛な案を混ぜて 10 個以上。言い換えは 1 つに数える
   A 音の素を届ける道 / B 鳴らし方（合成の方式）/ C 時間の扱い / D 質の壁の破り方 / E 使い道 / F 操作する場所・つなぐ道
2. 掛け合わせ: A×B×C の組で、1 つの軸からは出ない案を 10 個
3. 制約を外す: 「32 音が無かったら」「tick が無かったら」「パックをいつでも替えられたら」… 1 つずつ外して出た案を、
   制約を戻しても残る形に直す
4. 借りる: トラッカー音楽（MOD/XM/IT）・SoundFont/sfz・ボコーダー・音声コーデック（CELP・LPCNet・EnCodec）・ゲーム機の
   音源（SNES の BRR＋ADSR・FM）・グラニュラー・ベクトル量子化・UTAU/VOCALOID/MBROLA・自動採譜・音源分離
5. 絞る: 各案に 仕組み・期待できる質（何に近いか）・実機で確かめること・手間・危うさ（ライセンス・規約・壊れやすさ）・
   最初の一歩（手元の模型か実機のキューで何を測るか）
6. 出力: 全部の表 → 上位 10 の説明 → 今夜できる実験 5 つ（実機のキューに足せる形）→ 捨てた案と理由

# 守ること
- 実測と推測を分ける。測っていない端末（PC・iOS・コンソール）は推測と書く
- 素材はライセンスが明らかなもの（CC0・CC BY・Apache/MIT の音声合成・自作）だけ。Mojang の音や他人の曲を配らない。
  YouTube は規約上、権利のある動画（自分の・CC ライセンス）だけ
- いまあるものを壊さない。.github・auto/policy.json・auto/STOP・.env には触れない
```

### 2.3 制約を外して戻す

- **32 音が無かったら** → 何百声のコーデック。戻すと: 声を「聞こえの大事さ」で配る、束ねる時間を短く、楽器は 1 音 1 声で済むサンプラーへ
- **tick が無かったら** → 1 ms で鳴らす。戻しても残る: C3（seekTo）＋C4（束ねる）
- **パックをいつでも替えられたら** → 毎回その曲の mp3。戻すと: A2（参加するときに配る）・A11（転送で参加し直す）・A12（ライブラリ）
- **電話が 48 kHz で混ぜたら** → 高音。戻すと: 電話は 12 kHz まで（変えられない）、PC には D8
- **音を直接送れたら**（PCM を送る仕組みはゲームに無い）→ 戻すと: A2 がいちばん近い、どの音でもなら A4

### 2.4 借りる

- トラッカー音楽（MOD/XM/IT）: 「パターン＋サンプル」＝ B2 そのもの。IT の NNA（次の音が来たときの前の音の扱い）・包絡を fade で
- SoundFont/sfz: ゾーン・強さの層・ループ点 → 長い音はループ点から**同じファイルをもう 1 本 seekTo で重ねて渡す**（ゲームの音はファイル全体しか繰り返せない）
- MBROLA: 「音素・長さ・高さの目標」の列（.pho）＝ **声の MIDI**。B3 の曲の形はこれ
- UTAU/VOCALOID: 歌詞＋音符 → 素片。B12
- SNES（BRR＋ADSR）: 少ない声でも良く聞こえる配り方（同時発音の優先順位）
- CELP/LPC: 励振と声道を分ける考え。ゲームの中でフィルターは掛けられないので、**声道の形ごとに作った素**を選ぶ形に（B3・B4）
- 自動採譜（Basic Pitch: Apache-2.0）・音源分離（Demucs: MIT）: B7・B8

### 2.6 今夜できる実験（実機のキューに足せる形）

1. **p01 seek の置き方**: 同じ tick に「遅らせ 0 ms」と「k ms」（k = 1, 2, 3, 5, 8, 13, 21, 34）の 2 発、tick をまたぐ 37 ms 間隔の連打を
   束ねる／束ねない、2D と 3D。録音の立ち上がりの時刻から、差の誤差とばらつきを
2. **p02 ピアノ**: 同じ MIDI を サンプラー／いまの正弦波の道 で。手元で正確に鳴らした音を基準に ViSQOL
3. **p03 曲ごとのパック**: 元の曲の OGG を 1 本の SoundInstance で、10 秒の切れ端 2 本をつないで、seekTo・pause・resume（つなぎ目の隙間）
4. **p04 素片の声**: 読み上げの文を録って、録音を音声認識にかけた文字の誤り率（手元で whisper）
5. **p05 音割れ**: 大きい曲（ロック・EDM）でリミッターあり／なし

### 2.7 捨てた案と理由

- 音そのもの（PCM）をクライアントへ流す: そのためのパケットが無い（Endstone / LeviLamina でも、クライアントが鳴らせるのはパックの音だけ）
- スクリプトで音を加工する（フィルター・合成）: 音の計算をする API が無い
- Mojang の音を素にしたパックを配る: 配れない（バニラの音を /playsound で鳴らすのはよい: A5）
- 公開しているページの中で YouTube から取る: ブラウザからは取れない（CORS）うえ規約上もできない。手元の小さなサーバーの yt-dlp で、
  権利のある動画だけ
- VOICEVOX などのキャラクターの声から素片を作る: 多くの規約が別の音声合成を作ることを禁じている。素片は Apache/MIT/CC の声から

## 3. 作る順番（この結果から）

1. サンプラー＋seekTo（ピアノから）と p01 の実機 — **済**（p01・p04: 束の中は 1 ms、束ねるは 2 に。1 tick に始める数の上限は p06）
2. 曲ごとのパック（mp3 の質）と p03 — **済**（p03: 48 kHz に。内蔵のエチュードは ViSQOL 3.28）
3. 質の直し（リミッター・切り替え）と p05 — リミッターは**済**（`/spectral:limit`）、実機は p07（p05 は入る前のアドオンで走った）
4. 素片の声（読み上げ）と p02、そのあと音素の道の VC — 読み上げは**済**（`/spectral:say`・tools/speech.py）。p02（実機）で前の素は聞き取れず
   （子音が切れていた）→ 切り直し＋母音を次の子音で止めて手元の Whisper 0.26（p09 が実機）。VC は tools/exp/vc_units.py（0.71: 音素の時刻が要る）
5. ゲームの中の web、/connect の道 — **済**（Spectral Connect: ラボの OreUI のページ・ゲームの中の GeoUI のリモコン（bds/addons/spectral_remote）、
   変換器を `--ore`・`cmd:` の値・`mail:`（/connect へ）で育てた）。実機の /connect はまだ
6. 採譜＋分離、生演奏、歌声合成 — 生演奏は**済**（E2: ページの鍵・Web MIDI → 50 ms の束 → 弾いた間のまま。遅れは未実測）
