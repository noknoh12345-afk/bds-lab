# LeviKit

Linux VPS で **LeviLamina（BDS）** を一から構築し、次の4つをまとめて提供するセットです。

- **複数ワールド**：MoreDimensions で追加ディメンションを作り、`/dim` で切り替えます。ワールドごとのルール、取り込み（.mcworld）・書き出し・複製・ワールド単位の復元・リセットまで
- **マルチプロトコル**：Glacie + ProtocolLib で、サーバーと違うバージョンのクライアントも接続できます
- **参加したまま**のバックアップ／復元／再起動
- **管理パネル**：Web UI で上記すべてを操作します

```
            プレイヤー (UDP 19132)
                  │                    ┌──────────── 待機サーバー limbo (UDP 19134) ───────────┐
                  ▼                    │  再起動・復元・Mod更新中だけ参加者を預かる軽量BDS     │
┌──────── メインサーバー (Wine) ────────┐  TransferPacket  └──────────────────────────────────────┘
│ BDS 1.26.51 + LeviLamina 26.51.9      │ ───────────────▶        ▲  終わったら自動で戻す
│  ├ MoreDimensions 0.15.0  (追加次元)  │ ◀─────────────── ───────┘
│  ├ Glacie 3.10.2 + ProtocolLib (多版本)│
│  └ levikit-core  (/dim, 転送, 次元登録) │
└───────────────▲───────────────────────┘
                │ stdin/stdout（save hold/query/resume, levikit transfer …）
        levikit-panel (Node.js, systemd)  ── http://VPS:8080
```

## 2 つの版

| | LeviLamina 版（`install.sh`） | Endstone 版（`install-endstone.sh`） |
|---|---|---|
| 動かし方 | Wine の上の LeviLamina + C++ Mod `levikit-core` | Linux でそのまま動く Endstone + Python プラグイン `endstone-levikit` |
| 用意 | Wine、Windows ランナーでの Mod のビルド | Python 3.10 以上だけ（ビルド不要） |
| ワールド | 好きなだけ追加（MoreDimensions） | オーバーワールド・ネザー・ジ・エンドの 3 つ |
| ワールドのリセット・取り込み・複製、持ち物グループ、ボーダー、時間固定、モブのルール、ポータル | あり | なし |
| 別バージョンのクライアント（Glacie） | あり | なし（Endstone が対応する版だけ） |
| 動かしたままのバックアップ／復元／再起動、地図、タイムマシン、スケジュール、監視 | あり | あり（同じパネル） |
| `/dim` メニュー、ワールドごとのルール（ゲームモード・PvP・建築保護・入場制限・入退場のコマンド） | あり | あり |
| `/warp` `/hub` `/spawn` `/back` `/tpa`、BAN、メンテナンス、チャットのモード、権限グループ | あり | あり |

Endstone 版は同じ管理パネルを使います。パネルとサーバーの約束（`plugins/levikit-core/config/config.json` を読む、`@@LEVIKIT …` の行を出す、コンソールの `levikit …` に答える）を `endstone-levikit` も守るためです。この README の「使い方」で、上の表で「なし」のものを除いた部分が Endstone 版にも当てはまります。

### Endstone 版のインストール

```bash
sudo ./install-endstone.sh --accept-eula --public-host 203.0.113.10
```

Endstone が対応する BDS を自分で取得します。最後にパネルの URL とパスワードが出ます。systemd を使わない環境（コンテナなど）では `--root <フォルダー> --no-service` を付けると、起動コマンドだけを表示します。

## 2026-11-06 時点のバージョン事情（重要・LeviLamina 版）

| コンポーネント | 採用版 | 理由 |
|---|---|---|
| LeviLamina | **26.51.9**（BDS 1.26.51） | LL 本体は 26.60.2 まで出ていますが、MoreDimensions 0.15.0 が `>=26.51.7 <26.60.0` を要求するため |
| MoreDimensions | 0.15.0 | 最新版。API だけを提供し、ディメンションの登録は levikit-core が行います |
| Glacie | 3.10.2 | LL 専用のマルチプロトコル Mod（「BDS Server 1.26.51.x with LeviLamina 26.51.x」用） |
| ProtocolLib | 最新の安定版（lip が自動取得） | クライアントの対応範囲は ProtocolLib で決まります |

**クライアント 26.60 について**：ProtocolLib の最新 RC（1.10.1-rc.3）の対応範囲は **1.20.7x〜1.26.51** で、リリースノートに「26.60 への対応は含まない（開発中）」と書かれています。そのため、**現時点では 26.60 のクライアントはこのサーバーに入れません**。1.26.51 以前のクライアントは接続できます。

26.60 対応の ProtocolLib / Glacie が出たら、パネルの **Mod / プロトコル →「Glacie / ProtocolLib を更新」** を押してください。参加者を待機サーバーへ移してから更新し、終わったら自動で戻します。

MoreDimensions が LL 26.60 に対応したら、`install.sh` 冒頭の `LL_VERSION` / `MOREDIM_VERSION` と `mods/levikit-core/xmake.lua` を書き換えます。そのうえで、新しいフォルダへのクリーンインストール（ワールドは移行）を行ってください。LL 公式も、バージョンをまたぐときは別フォルダへの導入を推奨しています。

## 普通の BDS との違い

| | 普通の BDS | LeviKit |
|---|---|---|
| ワールド | 1ワールド3次元 | 1つのサーバーに**好きなだけワールドを追加**（プリセット: ロビー / 資源 / 建築 / PvP / イベント / スカイブロック / 第2ネザー・エンド）。`/dim` かコンパスで開く**アイコン付きメニュー**（人数・閉鎖・満員を表示）で移動し、**ワールドごとに最後にいた位置を記憶** |
| ワールドごとのルール | なし | ゲームモード自動切替・**持ち物グループ**（持ち物を分ける）・PvP・**ワールド限定の keepInventory**・**そのワールドで復活**・**建築保護**（全体/スポーン周辺, 建築許可者）・モブの自然スポーン・延焼・**ワールドボーダー**・**時間固定**・入退場タイトル/コマンド（キット配布など） |
| 入場制限 | なし | 開放/閉鎖（中の人は自動で外へ）・OP専用・許可リスト・人数上限。ネザーゲート等 `/dim` 以外の移動でも適用 |
| ワールドリセット | 不可（ワールドごと消すしかない） | **資源ワールドだけを参加したまま作り直し**（新しいシードも可・リセット前に自動バックアップ・スケジュールで「毎週月曜5時」なども可） |
| 別のワールドの持ち込み | 不可（サーバーのワールドを丸ごと差し替えるしかない） | **.mcworld（配布マップ・シングルのワールド・別サーバー）を新しいワールドとして追加**。参加したまま、今のワールドはそのまま。エンティティ ID は自動で振り直し |
| 荒らしの修復 | ワールド全体を巻き戻すしかない（他の人の建築も消える） | **タイムマシン**：Web の地図で範囲を選び、**その範囲だけ**を過去のバックアップの状態に戻す（オーバーワールドも可・参加したまま） |
| 地図 | なし | **上空マップ**を参加したまま生成（LevelDB を直接読む）。過去の時点に切り替え、**2つの時点で変わったチャンクを色付け**、プレイヤーの現在地を表示 |
| ワールド単位の操作 | なし | **1つのワールドだけ書き出し**（.mcworld でダウンロード）・**複製**（建築やイベント会場のコピー）・**バックアップから1つのワールドだけ復元**（他のワールドと持ち物はそのまま） |
| 移動手段 | /tp のみ | **ワープ**（`/warp`・オートコンプリート）・**ポータル**（範囲に入ると別ワールドへ）・**ロビー**（参加時に送る / `/hub`）・**`/tpa`**（ワールドをまたいで相手の所へ。入場制限は守る）・`/spawn`・**`/back`**（移動前・死んだ場所へ） |
| 権限 | OP かどうかだけ | **権限グループ**（`@staff` のように各ワールドの建築許可・入場許可・メンテナンス許可へまとめて指定） |
| チャット | 全体のみ | 全体 / 全体+[ワールド名] / **ワールドごと**（`!` で全体） |
| 別バージョンのクライアント | 入れない | Glacie で旧バージョン（〜1.20.7x）も接続できる |
| バックアップ | 止めてコピーするか、手作業で `save hold` | 遊んだまま1クリック。**重複排除ストア**で変わった分だけ保存（10分間隔でもディスクをほぼ使わない）。世代管理・ピン留め・メモ・DL・アップロード・**rclone で外部ストレージへ自動同期** |
| 復元 | 全員切断 → 停止 → 差し替え | **参加したまま**：待機サーバーへ自動転送 → 差し替え → 自動で戻す。差し替え前のワールドも自動で退避 |
| 再起動・Mod更新・設定変更 | 全員切断 | 参加したまま（待機サーバー経由） |
| BAN | 無い（allowlist のみ） | 名前/XUID で BAN、**期限付き**、理由表示、即時キック |
| メンテナンス | 無い | ワンクリックでメンテナンスモード（OP と許可リストだけ参加可） |
| 告知・定期処理 | 無い | **スケジュール**: 定期コマンド・告知・タイトル・**MOTD ローテーション**（{online} などの変数付き）・定期バックアップ・曜日指定の再起動 |
| 監視 | ログを見るだけ | **TPS・メモリ・CPU・人数のグラフ**、ワールド別の人数、クラッシュ自動再起動 |
| プレイヤー管理 | なし | 参加履歴・**累計プレイ時間**・**ワールド別の滞在時間**（どのワールドがよく遊ばれているか・よく来る人）・改名履歴、Web からチャットの閲覧と送信 |
| 設定ファイル | SSH で編集 | パネルで編集（JSON 構文チェック・自動 .bak・範囲制限） |
| 操作の記録 | なし | パネル操作の**監査ログ** |

## 必要なもの

- **x86_64** の VPS（Ubuntu 22.04 / 24.04、Debian 12 / 13）。メモリは **4GB 以上を推奨**（Wine 上の BDS と待機サーバーを動かすため）。ディスクは 10GB 以上
- 開けるポート：UDP 19132–19135、TCP 8080（パネル）
- GitHub アカウント（levikit-core のビルドに使います。無料の Actions で足ります）

## インストール

### 1. levikit-core をビルドする（初回だけ・約10分）

levikit-core は、ディメンション登録・`/dim`・待機サーバーへの転送を担当する C++ Mod です。LeviLamina の Mod は Windows 用 DLL なので、GitHub Actions（Windows ランナー）でビルドします。

1. このリポジトリ（bds-lab）を自分の GitHub に置きます
2. **Actions → levikit → Run workflow** を実行します
3. 完了したら Artifacts から `levikit-core-windows-x64` をダウンロードします（中身は zip）
   - `levikit-v1.0.0` のようなタグを push すると Release に zip が添付されます。その URL は `--kitcore-url` でそのまま使えます

### 2. VPS でインストール

```bash
# VPS 上で（このフォルダを scp/git clone で置いておく）
sudo ./install.sh --accept-eula \
  --public-host 203.0.113.10 \
  --kitcore-zip ./levikit-core-windows-x64.zip
```

`--accept-eula` は [Minecraft EULA](https://www.minecraft.net/eula) とプライバシーポリシーに同意したことを意味します。

インストーラーが行うこと：

1. WineHQ stable、xvfb、winetricks（LeviLamina 公式 Docker イメージと同じコミット）を導入し、VC++ ランタイムと .NET 10 を入れる
2. lip 0.37.0（Windows 版を Wine で実行）で `LeviLamina@26.51.9`（BDS 同梱）、`MoreDimensions@0.15.0`、`Glacie@3.10.2`（ProtocolLib 付き）を入れる
3. levikit-core を `plugins/levikit-core/` に展開する
4. 初回起動で設定ファイルとワールドを作る
5. 管理パネルを systemd サービス `levikit-panel` として登録し、自動起動する
6. ufw が有効なら、必要なポートを開ける

最後に表示される **パネルの URL とパスワード** を控えておいてください。パスワードは `sudo levikit-passwd` で再発行できます。

### 3. ポートを開ける

VPS 事業者のコントロールパネル（セキュリティグループなど）で **UDP 19132–19135** を開けます。パネルを外から使う場合は **TCP 8080** も開けます。

パネルは HTTP です。外に公開するなら HTTPS のリバースプロキシ（Caddy / nginx）を前に置くか、`--panel-host 127.0.0.1` で入れて SSH トンネル（`ssh -L 8080:127.0.0.1:8080 user@vps`）で使ってください。

## 使い方

### ワールド

パネルの **ワールド** 画面で管理します。プリセットを選んで「＋ ワールドを追加」を押し、カードを開いて調整してから「保存して適用」を押すと、参加者を待機サーバーへ移して再起動し、自動で戻します。ルールや表示名だけを変えたときは「保存してすぐ反映」で再起動なしに反映できます。

各ワールドのカードには4つのタブがあります。

| タブ | 内容 |
|---|---|
| 基本 | ID（`namespace:name`）、表示名、説明、メニューのアイコン（`textures/...`）、生成タイプ、シード、初回スポーン、着地のしかた |
| ルール | ゲームモード、持ち物グループ、PvP、死んでも落とさない、このワールドで復活、モブの自然スポーン、時間固定、建築保護（全体 / スポーン周辺 + 建築できる人）、ワールドボーダー |
| 入場制限 | 開放/閉鎖、OP 専用、人数上限、入れる人の限定 |
| 入退場 | 入場時のタイトル、入退場時のコマンド（`{player}` はプレイヤー名。例: PvP ワールドで入場時に装備を配り、退場時に `clear`） |

全体設定では、チャットのモード、ロビー（参加時に送る場所と `/hub` の行き先）、メニューを開くアイテム（既定はコンパス）、ゲームモード指定のあるワールドから出たときに戻すモードを決めます。

ゲーム内のコマンド：

```
/dim                 … ワールドメニュー（アイコン・人数・閉鎖/満員の表示付き）
/dim list | who      … 一覧 / 誰がどこにいるか
/dim info            … 今いるワールドのルール
/dim levikit:mine    … 直接移動
/dim setspawn        … (OP) 今いる場所をこのワールドのスポーンにする
/warp [名前]          … ワープ（名前はオートコンプリート）
/setwarp 名前 / /delwarp 名前              … (OP) ワープの作成・削除
/hub (/lobby)        … ロビーへ
/spawn               … 今いるワールドのスポーンへ
/back                … 前の場所へ戻る（ワールド移動・ワープ・/tpa の前の位置、死んだ場所）
/tpa 相手 → 相手が /tpaccept で許可（/tpdeny で拒否）… 相手の所へ移動（別のワールドにいても可）
/dimportal pos1 | pos2 | create 名前 行き先 | remove 名前 | list   … (OP) ポータル
```

`/tpa`・`/spawn`・`/back` は全体設定でオン/オフできます（「別のワールドの相手にも /tpa できる」「有効時間」も）。ワールドをまたぐ移動では入場制限（閉鎖・OP専用・許可リスト・人数上限）が守られ、持ち物グループも切り替わります。

ポータルの行き先は `world:ID`（そのワールドのスポーン）、`last:ID`（そのワールドで最後にいた場所）、`warp:名前` のいずれかです。

#### ワールドリセット（資源ワールドの作り直し）

ワールドのカードにある「リセット」で、そのワールドだけを作り直します。地形・建物・チェストの中身・エンティティが消え、ほかのワールドとプレイヤーの持ち物はそのまま残ります。

1. 先に参加したままバックアップを取ります（オフにもできます）
2. `config.json` の `pendingResets` に書き込み、必要ならシードを変えます（設定のまま / ランダム / 指定）
3. 参加したまま再起動します。levikit-core が起動直後、そのワールドが生成される前に LevelDB からチャンク（と、そこにいたエンティティ）を削除します。MoreDimensions の記録も消すので、新しい生成タイプとシードで作り直されます（ディメンション ID は BDS の名前→ID 表から同じものが再利用されます）
4. そのワールドでログアウトしていた人は、次に参加したときに新しいスポーン地点へ移動します（リセット回数 = epoch で判定）

スケジュール画面で「ワールドリセット」タスクにすると、定期的に自動で作り直せます（例: 毎週月曜 5:00、値 `levikit:resource random`）。

> 生成タイプやシードを変えても、既存ワールドの地形は変わりません。新しい値はリセットしたときに使われます（カードに「シード変更→リセットで反映」と表示されます）。

#### 別のワールドを取り込む（.mcworld）

ワールド画面の「＋ .mcworld を取り込む」で、統合版のワールドファイル（配布マップ、シングルプレイのワールド、別のサーバーのワールド）を**新しいワールドとして追加**します。今のワールドはそのままで、参加者は待機サーバー経由で自動で戻ります。

1. パネルがファイルを展開し、選んだ次元（既定はオーバーワールド）のチャンク・エンティティを取り出してパッケージ（`.lkdim`）にします。ワールド名・保存バージョン・範囲・エンティティ数がジョブのログに出ます
2. エンティティ ID を振り直します。統合版の ID はワールドごとに同じ値から始まるため、そのまま入れると元のワールドの動物などを上書きしてしまいます（`UniqueID`・`StorageKey`・`actorprefix` キー・digp・乗り物 `LinksTag`・リード `LeasherID` を揃えて書き換え）
3. 新しいワールド（既定の生成タイプは「何もない空間」= 範囲の外は空。オーバーワールドを選ぶと元のシードで続きを生成）を追加し、参加したまま再起動します
4. levikit-core が起動直後（そのワールドが生成される前）にパッケージを書き込みます。スポーンは元のワールドの level.dat から取ります

同じ ID を指定して「中身を置き換える」を選ぶと、既存のワールドを入れ替えます（先に自動でバックアップ）。

> サーバー（1.26.51）より新しいバージョンで保存されたワールドは警告が出ます。新しいブロックは正しく読み込まれないことがあります。プレイヤーデータ（持ち物・位置）は取り込みません。

#### 書き出し・複製・ワールド単位の復元

ワールドのカードにあるボタンで、そのワールドだけを操作します。

| ボタン | 内容 |
|---|---|
| 書き出し | そのワールドだけを単独の `.mcworld` にしてダウンロードします（参加したまま。その場でホットバックアップを取るか、過去のバックアップから選べます）。統合版でダブルクリックすると開けます。建築の配布や手元での保管に。ファイルは24時間で消えます |
| 複製 | 地形・建物・チェストの中身・エンティティごとコピーして新しいワールドを作ります。ルールもコピーされます。イベント会場の使い回し、建築の試し置きなどに。オーバーワールドも複製できます（生成タイプとシードを引き継ぐので、範囲外も同じ地形の続きになります） |
| 復元 | 選んだバックアップから**そのワールドだけ**を戻します。**オーバーワールド・ネザー・エンドも可**。ほかのワールド、プレイヤーの持ち物・位置はそのままです。先に今の状態を自動でバックアップします（参加者を待機サーバーへ移し、停止中にその次元のデータだけを入れ替えます） |

複製・復元・取り込みのあと、そのワールドでログアウトしていた人は、次に入るとスポーンへ移動します（地形が変わって埋まらないように）。

### ワールド専用のネザー

カスタムワールドのルールタブで「このワールド専用のネザー」に、ネザー型のカスタムワールド（プリセット「第2のネザー」）を選ぶと、そのワールドでネザーゲートに入ったときの行き先が通常のネザーではなく専用のネザーになります（座標は 1/8）。専用のネザーでゲートに入ると、元のワールド（座標 ×8）へ戻ります。資源ワールドとその資源ネザーをまとめてリセットする、といった運用ができます。1つのネザーは1つのワールド専用です。

### 高さの範囲について

MoreDimensions のワールドは生成タイプで高さの範囲が決まります（ネザー型 Y 0〜128、エンド型 0〜256、それ以外 −64〜320）。LeviKit はこれに合わせて次のように動きます。

- 取り込みでネザー/エンドを選ぶと、生成タイプを自動でネザー型/エンド型にします（オーバーワールドの地形はネザー型・エンド型に入れません）
- ネザー型・エンド型のワールドを書き出すと、書き出したワールドのネザー/エンドに入ります
- バックアップ時と今で高さの範囲が違う（生成タイプを変えてリセットした）場合、復元・範囲ロールバックは止めます
- スポーンの高さが生成タイプの範囲外なら保存時にエラーにします
- ネザー型への着地は天井の上に出ないようにします

### ワールドの削除

カードの「削除」では、既定で**ワールドのデータも消します**（次の起動で LevelDB と MoreDimensions の記録から削除）。データを残すと、同じ ID で作り直したときに前の地形と生成タイプが戻ってくるためです。残したい場合はチェックを外すか、先に「書き出し」で保存してください。

### アドオン / スクリプト（BDS 標準の仕組み）

LeviLamina の Mod とは別に、**普通の BDS と同じビヘイビアパック・リソースパック（Script API / GameTest 含む）**をパネルの **アドオン / スクリプト** 画面で扱えます。

- **取り込み**: .mcpack / .mcaddon / .zip をアップロード → manifest の modules から種類を判定して `behavior_packs/` `resource_packs/` に配置し、そのままワールドで有効化（`world_behavior_packs.json` / `world_resource_packs.json`）
- **有効化と順番**: チェックと ↑↓ で変更（上ほど優先）。BDS 標準のパックは「標準」と表示し、消せません
- **実験的機能**: ワールドの level.dat の `experiments`（Beta APIs = `gametest` など）を切り替え。反映時、サーバー停止中に書き換えます（元は `level.dat.levikit-bak`）
- **Script API の許可モジュール**: `config/default/permissions.json` の `allowed_modules`。`@minecraft/server-net`（HTTP）や `@minecraft/server-admin`（変数・シークレット）など BDS 専用モジュールをここで許可します。パックごとの変数・シークレットは「ファイル」画面で `config/<パックのUUID>/variables.json` / `secrets.json` を編集します
- `texturepack-required`（リソースパック必須）の切り替え
- **/reload**: スクリプトと関数だけを再起動なしで読み直すボタン
- コンソールでは BDS の全コマンド（`execute` `scriptevent` `structure` `camera` `script debugger listen` …）と LeviLamina / LeviKit のコマンドが補完候補に出ます

### 3D 観察ビュー

パネルの **3D 観察ビュー ↗**（地図画面の「選択を 3D で見る」からも）で、ワールドを**バニラのテクスチャ**で立体表示します。

- 「📷 今の状態を撮る」で参加したままスナップショットを撮り、指定した場所の周囲（最大 13×13 チャンク）をブロック単位で描きます。草・葉・水の色合い、草花の交差描画、水・ガラスの半透明に対応
- **参加者の現在地はリアルタイム**（levikit-core が3秒ごとに送る位置）。「追いかける」で選んだ人にカメラが付いていき、読み込んだ範囲から出るとその場所を読み直します（ブロックは撮った時点のもの）
- 描画は本家に近づけています（[cinnabar](https://github.com/cinnabar-mc/cinnabar) の描画方式を参考にした独自実装。cinnabar は PolyForm Noncommercial なのでコードは使っていません）
  - **ブロックの状態に応じた形**: ハーフ（上付き/下付き）・階段の向き・雪の層・カーペット・感圧板・耕地/道・チェスト・松明・ランタン・ドア/トラップドア（開閉）・柵/壁/板ガラス/鉄格子（隣とつながる）・フェンスゲート・ベッド・ケーキなど。横倒しの原木の向き
  - **なめらかな光**: 頂点ごとの環境光遮蔽（角が暗くなる）と面の向きの明るさ（本家と同じ比率）、屋根・洞窟の下は暗く
  - **バイオームの色**: 地表のバイオーム（Data3D）から草・葉・水の色を決め、周りと平均して境目をなめらかに
  - **液体**: 水位（liquid_depth）に応じた水面の高さ、水どうしの面は省略、溶岩は自己発光
  - 旧形式のワールド（1.18 以前の `log` `wool` など）は状態から木の種類・色を選びます
- マウスで回転・移動・拡大、WASD+QE で飛行、ダブルクリックでその場所に注目
- テクスチャは install.sh が Mojang 公式の [bedrock-samples](https://github.com/Mojang/bedrock-samples) から取得します（`--no-assets` で省略可）。描画には three.js（MIT）を同梱しています

> ボットとして接続して受信したチャンクを描く方式（mineflayer の viewer と同じ方式）は、統合版ではオンライン認証のため専用の Xbox アカウントが必要になるので採っていません。代わりにサーバー側のスナップショットを読みます。

### 高品質マップ（PapyrusCS）

統合版用の定番マップレンダラー [PapyrusCS](https://github.com/papyrus-mc/papyruscs)（Apache-2.0。メンテナンスが続いているフォーク ModifiedCommand/PapyrusCS 0.6.9）を取り込めます。拡大縮小できるタイル地図で、2回目からは変わったチャンクだけ描き直します。

1. このリポジトリの GitHub Actions が `papyruscs-linux-x64.zip` を作ります（.NET 6 で Linux 向けに組み直し、テクスチャを最新の bedrock-samples に差し替え）
2. `sudo ./install.sh ... --papyrus-zip ./papyruscs-linux-x64.zip`（または `--papyrus-url`）で導入（libgdiplus も入れます）
3. 地図画面の「高品質マップ（PapyrusCS）」で、選んだワールドを描きます（カスタムワールドも可。パネルがその次元だけのワールドを作って渡します）

組み込みの地図（マップ / タイムマシン）も、テクスチャがあれば**ブロック上面の実際の平均色**で塗ります。

### マップ / タイムマシン

パネルの **マップ / タイムマシン** 画面で使います。

1. 「📷 今の状態を撮る」で、参加したままスナップショット（ホットバックアップ）を取り、そのワールドの上空マップを描きます。過去のバックアップを選んで「この時点を描く」もできます
2. 「比べる」で別の時点を選ぶと、その間に**変わったチャンクが赤**、新しく生成されたチャンクが水色で表示されます（チャンクごとの全データの指紋を比較）。いつ・どこが荒らされたかを探せます
3. Shift+ドラッグで範囲を選び、「戻す時点」を選んで「選択範囲をこの時点に戻す」を押すと、**その範囲だけ**が当時の地形・建物・チェストの中身・動物に戻ります。範囲の外、他のワールド、プレイヤーの持ち物はそのままです。先に自動でバックアップを取ります

範囲ロールバックは、参加者を待機サーバーへ移してメインサーバーを止めている間に、パネルが LevelDB を直接書き換えます（BDS が読み込み済みのデータとぶつからないので、オーバーワールドでも安全に書けます）。戻したエンティティの ID は振り直します。書き換え後のデータベースは読み直して検証してから差し替え、失敗したら元のまま起動します。

> 地図は1ブロック1ピクセルです。色はブロック名から決めています（草・水・砂・石など。知らないブロックは灰色）。大きなワールドは中央の約 200×200 チャンクまでを描きます。範囲ロールバックはワールドのデータベース全体を一度読み書きするため、大きなワールドでは時間とメモリが必要です。プレイヤーの現在地は levikit-core が3秒ごとに送ります。

### 権限グループ

BAN / メンテナンス画面の「権限グループ」で、名前を付けたプレイヤーの集まりを作れます。ワールドの「建築できる人」「入場を許可する人」、メンテナンスの許可リストに `@グループ名` と書くと、その全員が対象になります。メンバーを変えれば、すべてのワールドに一度に反映されます。存在しないグループを書いたり、使われているグループを消したりすると保存時にエラーになります。

### ワールド別の統計

ワールドのカードに、累計滞在時間・訪れた人数・移動回数・よく来る人が表示されます。プレイヤー履歴には、それぞれがよくいるワールドが表示されます（levikit-core の `WORLD_CHANGE` から集計）。

### ワールドごとのゲームモード / 持ち物グループ

ディメンション画面の「ゲームモード」「持ち物グループ」で設定します。初期設定では「建築ワールド(フラット)」がクリエイティブで、持ち物グループは `creative` です。

- グループが違うワールドへ移ると、今の持ち物（インベントリ・防具・オフハンド・エンダーチェスト）を保存し、移動先グループの持ち物に入れ替えます
- `/dim` での移動だけでなく、ポータル・`/tpdim`・死亡リスポーンでも、ディメンションが変わったことを検知して切り替えます
- データはワールドフォルダ内の `levikit/` に保存するので、バックアップと復元に一緒に含まれます（バックアップ直前に `levikit save` で確定させます）
- 経験値とステータス効果は共通です

### BAN / メンテナンス / 参加メッセージ

**BAN / メンテナンス** 画面（またはプレイヤー一覧の BAN ボタン）で操作します。保存すると即時に反映し、該当する参加中のプレイヤーは切断されます。期限付き BAN は期限が来ると自動で解除されます。


### 待機サーバー（limbo）

メインのフォルダから本体と Mod を rsync して自動で作られます。中身はアドベンチャーモード・ピースフルの平坦な待機ワールドです。モードは設定画面で選べます。

- **必要なときだけ**（既定）：作業のときだけ起動します。起動に数十秒かかります
- **常時**：常に起動しておくので切り替えが速くなります。その分メモリを消費します
- **使わない**：参加したまま系の操作がすべて「通常モード」（予告して切断）になります

プレイヤーの転送には **公開ホスト（設定画面）** が必要です。ドメインかグローバル IP を入れてください。

### Mod の追加

パネルの **Mod / プロトコル** で `lip install github.com/owner/repo` を実行できます。起動中なら参加者を待機サーバーへ移してから実行し、待機サーバーにも同期します。LeviLamina 本体のバージョンは変えないでください。

## 制限事項・注意

- **levikit-core は、この環境では LeviLamina 26.51.9 / MoreDimensions 0.15.0 の実ヘッダーに対する構文・型チェックまでしか行えていません。** Windows（MSVC/clang-cl）でのリンクと実機での動作は、Actions のビルドと初回起動で確認してください。ビルドが失敗したら、ログを渡してもらえれば直します
- **ワールドリセット・取り込み・複製・ワールド単位の復元**は、BDS 自身のストレージ API（`DBStorage::forEachKeyWithPrefix` / `saveData` / `deleteData`。書き込みキャッシュ経由、最後に `flushToPermanentStorage`）で、そのワールドが生成される前にチャンクキーを書き換えます。最初は**バックアップを取った状態で**、重要でないワールドを使って実機で確かめてください（パネルは置き換え・復元・リセットの前に自動でバックアップします）
- 取り込み・書き出しのワールド処理（LevelDB の読み書き・NBT・エンティティ ID の規則）は、パネル側（Node.js）では本物の統合版ワールド（1.18 / 1.19.70 / 1.21.72 で保存されたもの）で検証済みです。ストレージキーの規則（`StorageKey = big-endian((-上位32bit) << 32 | 下位32bit)`）は実ワールドの値と一致することを確認しています。levikit-core 側のパッケージ読み込み・キーの組み立て・ID 生成（`Format.h`）は Linux でネイティブにビルドし、JS 側と突き合わせています（`node test/toolkit.js`）。BDS 上で書き込んだ後にゲームが正しく読むかは実機で確認してください
- 地図の描画（サブチャンク v8/v9 のパレット・Data3D の高さマップ）と 3D 観察ビューは、1.18 と 1.21.72 で保存された実ワールドで確かめています（3D はヘッドレス Chrome の WebGL で表示を確認）
- **PapyrusCS の Linux ビルドは、この環境では外部コードのビルドができなかったため未検証です**（Actions の `papyrus` ジョブで作られます）。.NET 6 への組み直しで問題が出たら、ログを渡してもらえれば直します。PapyrusCS が無くても、組み込みの地図と 3D 観察ビューは使えます
- 実験的機能のキー名は BDS のバージョンで変わることがあります。一覧にないものは「ほかのキー」で追加できます（level.dat に既にあるキーは自動で表示）
- 取り込み・複製は、ワールドの大きさに応じてメモリを使います（複製は元ワールドのチャンクを一度メモリに読みます）。数 GB 級のワールドは VPS のメモリに注意してください。アップロードの上限は既定 2048 MB（`levikit.json` の `panel.maxUploadMB`）
- **死亡時の持ち物保持**（ワールド限定 keepInventory）は、LeviLamina の PlayerDieEvent が BDS のドロップ処理より前に呼ばれることを利用し、持ち物を退避してから空にします。リスポーン後、ディメンションの移動が落ち着いてから（約1秒後）復元します
- **時間固定**はクライアントの見た目だけです（SetTimePacket を定期送信）。作物の成長やモブのスポーンはサーバーの時間で決まります
- **持ち物グループの入れ替え**は、BDS 内部のアイテム NBT を保存・復元する処理です（LegacyScriptEngine と同じ API を使用）。実機で、エンチャント・シュルカーボックス・名前付きアイテムが正しく往復するか、最初は重要でないアイテムで確かめてください。不安なら設定でオフにできます
- **パネルは擬似 BDS を使った結合テストで検証済みです。** `node test/e2e.js`（27項目: ホットバックアップの切り詰め・重複排除・GC・tar、参加したまま復元、待機サーバーの往復、ワールドリセット、ワープ/ポータル/ロビー、開放・閉鎖、BAN・メンテナンス、チャット、メトリクス、スケジュール、ファイル編集、ディメンション適用など）と、本物の LevelDB を持つ擬似サーバーでの `node test/e2e-worlds.js`（.mcworld 取り込み・書き出し・複製・ワールド単位の復元・地図と差分・範囲ロールバック・滞在時間・権限グループ）です。擬似サーバーは levikit-core の起動時処理（取り込み・複製）を同じ規則の JS で再現したもので、levikit-core そのものではありません。UI はヘッドレス Chrome で全画面を表示し、JS エラーが出ないことを確認しています
- Glacie 3.10.2 から独自の待受ポート設定（`raknet-port` / `raknet-portv6`）が増えました。パネルは起動のたびに Glacie の設定 JSON を走査し、server.properties のポートと揃えます（メインと待機サーバーのポート衝突を防ぐため）
- 転送（TransferPacket）は、クライアントがそのホスト・ポートに直接つなげることが前提です。外部サーバー接続そのものに制限があるゲーム機では、もともと参加できる経路が必要です
- Glacie は「All rights reserved」の配布物です。このキットには同梱しておらず、lip が公式 Release から取得します
- `install.sh` は Wine 上で LeviLamina 公式 Docker イメージ（`ghcr.io/liteldev/levilamina-server:latest-wine`）と同じ手順を再現していますが、Docker は使いません

本物のサーバーで確かめるもの（GitHub Actions の `levikit` ワークフローが全部走らせます）:

```bash
./install-endstone.sh --accept-eula --root /tmp/lk --no-service && node test/e2e-endstone.js /tmp/lk   # パネル ⇄ 本物の Endstone
node test/real-server.js <サーバーのフォルダー> -- <起動コマンド>   # 1 回起動して READY / DIMS / PLAYERS を見る（LeviLamina も Endstone も）
```

- `endstone/tests.txt` は、本物の Bedrock クライアントを参加させる試験です（参加・`/dim`・ワープ・`/tpa`・建築保護・BAN・再起動）。bds-lab の `dev` ブランチにある Endstone ラボで `node lab.mjs end go -a levikit` として走らせます。
- Endstone 版で確かめていないこと: プレイヤーがいる状態での待機サーバー経由の再起動・復元。転送の命令（`levikit transfer`）が全員に届くことと、待機サーバーなしの再起動・バックアップは確かめています。

- `panel/` は依存なしの Node.js です（http + SSE）。API の認証はセッション Cookie（HttpOnly / SameSite=Strict）で、状態を変更するリクエストには `X-LeviKit: 1` ヘッダーが必要です。ログインは1分に5回までに制限しています
- `mods/levikit-core/` は LeviLamina Mod テンプレート準拠の xmake プロジェクトです
- KitCore が出力する `@@LEVIKIT <KIND> <json>` 行（READY / PLAYERS / TRANSFER / DIMS / JOIN / LEAVE / DENIED / CHAT / STATS / INV_SWITCH / WORLD_CHANGE / RESET / POS / IMPORT / IMPORT_FAILED / CLONE / CLONE_FAILED / RELOADED）をパネルが読み取ります
- levikit-core のソースは `Core.cpp`（設定とイベント配線）/ `Worlds.cpp`（マルチワールド本体・/back・/tpa）/ `Reset.cpp`（リセット）/ `Import.cpp`（取り込み・複製）/ `Format.h`（キー形式・ID・パッケージ。BDS 非依存）/ `Inventory.cpp`（持ち物）/ `Commands.cpp`（コマンド）/ `Util.cpp` に分かれています
- 設定ファイルは読み込み時に既定値で補完され、古い形式は自動で移行されます（v3 でルールを `rules` に、v4 で権限グループ・/tpa 設定・取り込み/複製の予約を追加）
- パッケージ（`.lkdim`）の形式: 16バイトのヘッダー `"LKDIM\x02\0\0" u32 2 u32 件数` のあと、zlib 圧縮フレーム（`u32 圧縮長 u32 元の長さ`）が続き、中身は `u8 種類(1=チャンク 2=digp 3=エンティティ) u32 キー長 キー u32 値の長さ 値` の連結です。チャンクのキーはディメンション ID を除いた形で、levikit-core が書き込み先の ID を付けます
- KitCore のコンソール命令: `levikit transfer <host> <port>` / `players` / `dims` / `stats` / `reload` / `save` / `motd "<text>"`
